# 动态子 Agent 实施计划

## 当前任务与目标

Leader 按任务创建独立 Agent Run，分配工具与上下文，可选用已有 Agent 作为配置模板。
子任务执行使用持久配置快照，工具集合同时约束模型可见工具和实际执行器。

## 如何修改

### 执行创建与快照

`SubAgentMiddleware` 向 Leader 暴露 `spawn_agent(task, tools, context, template)`。
任务参数只描述任务与能力选择；父 Run、用户、请求和工具调用身份来自运行时。
`ask_user` 与 spawn 出现在同一批工具调用时，返回错误工具结果，等待用户澄清后重新委派。

服务锁定并验证父 Run，通过请求和工具调用身份保持幂等。无模板使用通用执行器配置；
有模板时复制启用子角色的配置，显式工具集合覆盖模板默认值。
任务和补充上下文作为独立输入消息持久化。子 Run 的 `agent_id` 使用固定通用执行器，
`created_by_run_id` 指向父 Run，`run_metadata.spawn` 保存模板来源及完整 `agent_config` 快照。
事务提交后才投递子 Run ID。

Thread Service 从持久快照构建子 Agent Context，运行身份由 Worker 重新注入。
模板之后的修改不改变这次任务的指令、模型和工具；状态、结果、等待及取消沿用 Run 服务。

验证覆盖无模板创建、模板默认及覆盖、重复调用、越权与父 Run 终态拒绝、配置独立和快照执行。

取消入口先锁定目标 Run 再查询子树，与 spawn 创建使用同一父行锁；提交后发布信号。

### 工具选择与执行

工具目录统一现有网络/知识检索、卫星目录、MCP 和文件系统工具的名称与说明。
Leader 使用 `list_agent_tools` 按需获取目录，`spawn_agent.tools` 使用目录中的工具名称。

显式 `[]` 表示无工具；无模板且省略 tools 也使用空集合。有模板且省略 tools 时，
解析模板的工具默认值；历史未限定工具的模板在创建时将现有集合物化为明确列表。
工具名称解析失败时不创建子 Run，仅选择本地工具或空集合时无需发现 MCP。

SubAgentGraph 按配置快照构造工具和中间件。文件系统中间件的工具在注册前过滤，
外层调用检查拒绝模型伪造的未分配工具调用，使其无法触发沙箱初始化或执行副作用。

验证覆盖工具目录、未知名称、模板默认、显式空集合、不同工具集合隔离，以及真实图执行中
选中工具成功、未选工具失败且执行函数与沙箱初始化均未被调用。

## 实施步骤

1. 实现工具目录及显式工具集合，覆盖普通工具、MCP 和文件系统工具。
2. 接通可选模板的 spawn 服务，保存独立输入、模型及配置快照。
3. 在 Leader 注册动态委派入口，执行端消费快照并保持父子 Run 身份。
4. 验证无模板、模板覆盖、配置独立、禁止未选工具执行，以及已有委派与取消路径。

## 验收标准

- 不选择模板也能创建子 Run；每次任务有自己的 thread、输入和状态。
- 显式空工具集合不注册任何任务工具，未知工具在创建前拒绝。
- 同一模板的不同任务可以拥有不同工具集合，模板变化不改变已创建任务。
- 子 Run 的创建者、用户身份、持久化与队列投递顺序可验证。
- Leader 能发现可分配工具，查询、等待及取消动态子 Run。

验证结果：114 项定向测试、45 个子用例通过；使用 SQLite 和模拟模型覆盖真实工具调用与持久化。
源码编译、改动文件 Ruff 和 `git diff --check` 通过。
