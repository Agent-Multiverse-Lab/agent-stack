# Settings 模型管理

## 范围

在现有 Settings 对话框内增加 Models 选项，管理可用于 Chat 的单模态/多模态模型。
当前阶段按已确认设计实施页面与管理 HTTP 接口。
后端供应商、模型列表与运行时连接合同见 `docs/spec/model/provider-management/spec.md`。

## 要求

### MODEL-SETTINGS-001 布局

保留 Settings 左侧设置导航，新增 Models。选择 Models 后，右侧内容分成模型选项列和详情列。
桌面样例采用约 1120px 宽的对话框，设置导航约 168px、模型选项约 216px，详情填满剩余空间。
三栏共用白色背景，使用黑灰文字，通过留白区分区域；列标题、表单边缘和行间距统一对齐。
保留外层对话框，配置区和具体模型不套卡片，不增加分栏边框或底部操作容器。
仅在配置与模型列表之间保留一条细分隔线，模型行之间不加线；输入框使用浅色背景与弱边框。

### MODEL-SETTINGS-002 模型选项

模型选项来自管理员调用 `GET /api/models/providers` 得到的全局响应，前端不维护固定供应商数组。
系统首批预置为 DeepSeek 和 Qwen；后端新增完整预置或全局数据库中存在其他供应商时，
页面无需修改选项清单代码即可展示。
操作图标统一使用现有 Lucide；已知厂商标识使用本地彩色 SVG，未知厂商使用中性模型图标，
不因缺少品牌资源隐藏服务端记录。点击选项显示对应详情，选中项仅用背景和字重标识。
具体连接实例与配置数据继续以供应商记录为准；类型名称不替代 provider_id。

### MODEL-SETTINGS-003 详情

从上到下排列：名称与启用开关、模型连接配置、具体模型名称和功能描述。
连接配置仅展示 API Key、Base URL，不展示协议和请求头选项。
API Key 使用 Field 布局，标签位于输入框上方，下方显示密钥加密存储说明；Base URL 保留容器内上方名称、下方字段值。
API Key 与输入值同排的右侧内嵌单色插头图标用于检测，与密钥显隐控件并列；不显示“检测”文字和按钮底色，底部不再单独展示测试连接按钮。图标按钮通过 aria-label 提供无障碍名称。点击检测时直接把当前未保存的 Base URL 与 API Key 发送给后端，由后端访问供应商模型列表接口验证凭据，不要求先选择聊天模型。
具体模型项将 model_id 与能力合为一行，名称居左，能力以统一单色彩块包裹并整体靠齐行最右侧，不另起描述行；只接入 Chat 模型。
模型列表不展示请求体覆盖字段或字样；此展示调整不修改后端参数合同。
模型行默认无背景、无边框，hover 时仅加深行背景，不增加额外控件或展开内容。
保存、检测、获取模型仅作为必要的操作按钮。

### MODEL-SETTINGS-004 文案

页面只显示设置导航、模型选项、字段标签、操作按钮、具体模型名称及功能描述。
除 API Key 加密存储说明外，不添加说明段落、宣传文案、功能引导、提示卡、统计数据或其他未要求的描述性内容。
样例图中的模型记录只用于视觉评审，不宣称来自真实 API、已保存或连接测试成功。
能力标签来自供应商明确返回的聊天能力元数据，保存到 enabled_models 的可选 capabilities 列表；无元数据时不猜测能力。
远程发现的模型由管理员在选择界面明确勾选后加入聊天模型列表，不自动启用全部结果。

### MODEL-SETTINGS-005 管理接口

在现有 `/api/models` 下保留 `/providers` 列表及 `/providers/{provider_id}` 保存接口，
以及对应 `/discover`、`/test` POST 接口。全部 Provider 管理接口要求管理员授权，普通登录用户只能读取
`GET /api/models` 的全局公开模型列表。管理接口返回全局供应商摘要，选择供应商后通过
GET `/providers/{provider_id}` 加载脱敏详情。
列表和详情由后端直接读取全局 PostgreSQL；Redis 只保存 `GET /api/models` 所需的已启用模型公开列表，
不参与 Settings 详情拼装。浏览器不直接连接 Redis，也不接收 Redis key、密文或额外请求头。
管理员授权由 Auth Domain 基于部署配置 `ADMIN_EMAILS` 提供；配置为空时没有用户拥有管理权限，不能把该入口开放给全部 AuthenticatedUser。
Chat 模型列表与运行时 ChatModel 都使用同一条全局 Provider 配置。
探测使用当前表单参数，仅在 Base URL 未改变时允许省略 API Key 并沿用平台已保存密钥；不通过保存配置间接触发探测。
保存仅修改页面字段；同地址下保留未展示的参数。变更 Base URL 必须重新提供已有 Key，私有请求头不自动转发或保留到新地址。
API Key 不回传、不写入浏览器持久化存储，校验错误不返回原始输入值。
应用层不再依据浏览器页面协议或管理请求 scheme 拒绝模型设置；该协议检查不作为模型凭据测试。
生产部署仍应通过 HTTPS 保护包含 Key 的请求传输，不增加自定义前端加密协议。
开发者工具可以看到本人输入的请求字段，此限制不宣称隐藏浏览器已持有的信息。
反向代理部署只信任明确配置的代理地址，不直接信任客户端伪造的 X-Forwarded-Proto。

### MODEL-SETTINGS-006 界面状态

`SettingsModels` 的 React 本地状态负责全局供应商摘要、按 provider 缓存的详情草稿、密钥输入和界面操作。
列表和详情均只存在内存中，API Key 不进入共享 Context 或浏览器持久化存储。换账号或退出时同步清空列表、详情、草稿和操作结果，
旧请求结果不得写入新账号状态。
首次列表请求成功后选中响应中的第一个供应商；当前选中项不再存在时也回退到第一项。
响应为空时展示原位空状态，不在前端合成 DeepSeek、Qwen 或其他占位选项。

## 验收

- 画面清晰呈现“设置导航 / 模型选项 / 模型详情”三栏。
- 管理员模型选项与全局 API 返回一致，前端不硬编码供应商列表；未知供应商仍可展示和编辑。
- 普通用户不显示 Provider 管理入口，直接调用管理、发现或测试接口返回 403。
- 详情同时容纳启用开关、连接配置和模型名称及功能描述。
- 区域以留白组织，避免嵌套容器，仅保留少量必要分隔线。
- 除 API Key 加密存储说明外，不出现额外说明性内容。
