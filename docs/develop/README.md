# Develop 功能设计说明

本目录存放较大功能或跨模块改动的单文件设计草稿（一件事一个 `<topic>.md`），用于先对齐方向再编码和迭代。

## 写什么（建议 30~80 行）

- **目标与现象**：要解决什么问题，期望的用户体验或系统行为是什么。
- **关键边界与取舍**：最核心的几条约束与选型理由。
- **大概改动方向**：涉及哪几块（API / Worker / 持久化 / 前端），各负什么责。
- **核心验收场景**：实现后重点检查与手动验证的几个场景。

## 生命周期

- 具体类定义、字段和接口以源码与测试为准。
- 功能稳定合入后，将影响系统边界的长期约束补充几句到对应 `docs/architecture/<system>-system.md`，并删除本目录下的过程设计文件（Git 保留演进历史）。
